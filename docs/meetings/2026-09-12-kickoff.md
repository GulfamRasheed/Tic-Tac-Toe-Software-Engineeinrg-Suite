## Discussion and decisions

1. GitHub will be the shared source of truth for code, documentation, designs, tests, and team progress.
2. The default integration branch is `main`. Members will work on short-lived task branches and contribute through pull requests.
3. Project artifacts will be stored in their matching repository folders so they remain easy to review and maintain.
4. The project will use Semantic Versioning. Early development releases will use `0.x.y`; the first usable baseline is planned as `0.1.0`.
5. Work will be managed iteratively with small issues, clear acceptance criteria, peer review, testing, sprint reviews, and retrospectives.
6. Detailed repository, versioning, and Agile instructions are maintained in `CONTRIBUTING.md`.

## Working instructions shared by the lead

- Pull `main` before starting work and create a branch for each task.
- Use GitHub issues to state the goal, owner, and acceptance criteria.
- Do not push feature work directly to `main`; open a pull request.
- Keep commits small and use clear, action-oriented messages.
- Request a peer review and address feedback before merging.
- Update tests and documentation whenever behavior or decisions change.
- Report blockers early and update task status regularly.
- Follow the versioning and Agile guidance in `CONTRIBUTING.md`.
