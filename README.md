# Tic-Tac-Toe Software Engineering Suite

A team software-engineering project for designing, building, and testing a usable Tic-Tac-Toe game. The repository keeps product documentation, design work, implementation, tests, meeting records, and reports in one place.

## Repository structure

```text
.
|-- docs/
|   |-- requirements/   # Product and functional requirements
|   |-- architecture/   # Architecture and repository decisions
|   |-- ui-ux/          # Wireframes, prototypes, and design notes
|   |-- meetings/       # Agendas, minutes, decisions, and action items
|   |-- testing/        # Test plans, cases, and QA rules
|   `-- reports/        # Progress and final reports
|-- tests/              # Automated tests
|-- .github/
|   |-- ISSUE_TEMPLATE/ # GitHub issue templates
|   `-- pull_request_template.md
|-- README.md
|-- CONTRIBUTING.md
|-- CHANGELOG.md
`-- .gitignore
```

Implementation folders will be added by the frontend developer when the technology and initial layout are confirmed. Do not place application code inside `docs/`.

## Getting started

1. Clone the repository.
2. Read [CONTRIBUTING.md](CONTRIBUTING.md) before making changes.
3. Select or create a GitHub issue for the work.
4. Create a short-lived branch from `main`.
5. Commit, push, and open a pull request.
